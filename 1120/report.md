## 고급 프로시저


# 1.스택 프레임

* 정의: 스택 프레임(또는 활성 레코드)은 전달된 인자, 서브루틴 복귀 주소, 지역 변수, 저장된 레지스터를 위해 스택에 할당된 영역입니다.
* 생성 과정 (Stack Frame Creation Process):
인자 푸시 (Push Arguments) 
EBP 푸시 (Push EBP): 현재 베이스 포인터(EBP) 값을 저장합니다.
지역 변수 할당 (Allocate Local Variables).
서브루틴 호출 (Call Subroutine): 복귀 주소를 푸시합니다.
EBP를 ESP로 설정 (Set EBP to ESP): EBP를 현재 스택 포인터(ESP)로 업데이트하여 스택 프레임의 기준점을 설정합니다.
레지스터 저장 (Save Registers).

# 2. 인자전달
* 레지스터 인자의 단점: 레지스터를 인자로 사용하면 호출 전/후에 레지스터를 저장(push)하고 복원(pop)하는 과정이 많아져 코드가 복잡해지고 성능 이점이 상쇄될 수 있습니다. 이를 보완하기 위해 Microsoft는 fastcall 규약을 도입했습니다.
* 값 전달 (Passing by Value): 인자의 값 복사본이 스택에 푸시됩니다.
* 참조 전달 (Passing by Reference): 객체의 메모리 주소(오프셋)가 인자로 전달됩니다.
* 고수준 언어는 배열을 항상 참조(주소)로 서브루틴에 전달합니다.
* 스택 인자 접근: 스택 인자는 베이스 포인터(EBP)를 기준으로 [ebp+8], [ebp+12]와 같이 오프셋을 사용하여 접근하며, 이를 **명시적 스택 인자(Explicit Stack Parameters)**라고 합니다. 코드를 읽기 쉽게 하기 위해 기호 상수를 정의하여 사용할 수 있습니다.

# 3. 스택 정리 및 호출 규약
* C 호출 규약 (C Calling Convention): C 및 C++에서 사용되는 규약입니다.
* 인자는 스택에 역순으로 푸시됩니다 (예: AddTwo(A, B) 호출 시 B를 먼저, A를 나중에 푸시).
* 호출된 서브루틴에서 복귀한 후 **호출자(caller)**가 add esp, 8과 같은 명령을 사용하여 스택에서 인자를 제거(스택 정리)합니다.

STDCALL:
* **호출된 서브루틴(callee)**이 스택 정리를 담당합니다.
* RET 명령어에 인자(매개변수가 차지하는 총 바이트 수)를 전달하여 복귀와 동시에 스택을 정리합니다 (예: ret 8).

# 4. 지역 변수 및 스택 관리
* 지역 변수 (Local Variables): 단일 서브루틴 내에서 생성, 사용, 소멸되는 변수이며, 런타임 스택에서 EBP 아래에 생성됩니다.
* 스택 프레임 해제: 함수가 끝나기 전에 스택 포인터(ESP)를 EBP 값으로 다시 할당하여 지역 변수를 스택에서 해제합니다.
* ENTER 명령어: 호출된 프로시저를 위한 스택 프레임을 자동으로 생성합니다. 지역 변수를 위한 공간을 예약하고 EBP를 스택에 저장합니다.
* LEAVE 명령어: ENTER의 동작을 역순으로 되돌려 프로시저의 스택 프레임을 종료하고 ESP와 EBP를 복원합니다.

# 5. 재귀
* 재귀 서브루틴은 자신을 직간접적으로 호출하는 함수입니다.
* 유용한 재귀 서브루틴은 항상 종료 조건을 포함해야 합니다.
* 재귀 호출이 해제될 때(unwind) 스택에 저장된 임시 데이터(스택 인자)가 유용하게 사용될 수 있습니다.

# 6. 고급 지시어

* INVOKE: 32비트 모드에서 사용 가능한 매크로로, 인자를 스택에 푸시하고, 프로시저 호출 후 호출 규약에 따른 스택 정리까지 자동으로 처리하여 CALL 명령을 편리하게 대체합니다.
* ADDR 연산자: INVOKE와 함께 사용되며, 변수의 주소를 인자로 전달하는 데 사용됩니다.
* PROC 지시어: 명명된 인자 목록과 함께 프로시저를 정의하는 데 사용됩니다.
* 모듈성: PUBLIC, PRIVATE, EXTERN, EXTERNDEF 등의 지시어를 사용하여 프로시저와 변수의 접근성을 제어하고 모듈성을 높일 수 있습니다.
